🧭Méthodologie — comment ces vulnérabilités ont été trouvées

1

Reconnaissance (Playwright)

Le crawler rend réellement le JavaScript de la cible, découvre les URLs internes, extrait les paramètres de formulaires/liens/appels API et repère les sinks DOM (innerHTML, eval…). Il n'injecte rien à ce stade : il cartographie uniquement la surface d'attaque.

2

Scan automatisé (XSStrike / DalFox)

Chaque paramètre découvert est fuzzé dans un conteneur Docker jetable : XSStrike teste des variantes de payloads XSS par similarité de réponse, DalFox injecte et analyse le contexte de réflexion (HTML, attribut, JS) — y compris sur les formulaires POST authentifiés.

3

Normalisation (parser.py)

Les sorties hétérogènes (texte XSStrike, JSON DalFox) sont converties en un schéma unique (payload, paramètre, contexte, sévérité), dédupliquées pour éviter les doublons entre outils.

4

Vérification par exécution réelle

Chaque payload retenu est rejoué dans un vrai navigateur (Playwright) en reconstruisant l'URL exacte d'injection. Une vulnérabilité n'est marquée Confirmé que si une boîte de dialogue JS s'est réellement déclenchée — pas seulement un score heuristique. Le détail par vulnérabilité ci-dessous montre l'URL de reproduction exacte et les étapes suivies.
