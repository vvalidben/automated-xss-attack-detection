🧭Methodology — how these vulnerabilities were found

1

Reconnaissance (Playwright)

The crawler actually renders the target's JavaScript, discovers internal URLs, extracts form/link/API-call parameters, and spots DOM sinks (innerHTML, eval…). It injects nothing at this stage: it only maps the attack surface.

2

Automated scan (XSStrike / DalFox)

Each discovered parameter is fuzzed inside a disposable Docker container: XSStrike tests XSS payload variants by response similarity, DalFox injects and analyzes the reflection context (HTML, attribute, JS) — including authenticated POST forms.

3

Normalization (parser.py)

Heterogeneous outputs (XSStrike text, DalFox JSON) are converted into a single schema (payload, parameter, context, severity), then deduplicated to avoid overlap between tools.

4

Real-execution verification

Each retained payload is replayed in a real browser (Playwright) by reconstructing the exact injection URL. A vulnerability is only marked Confirmed if a JS dialog actually fired — not just a heuristic score. The per-vulnerability detail below shows the exact reproduction URL and the steps followed.
